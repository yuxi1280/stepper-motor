================================================================================
  EPS 执行设备 CAN 通信协议 v3        （步进 + 舵机执行板，给上位机/网关用）
  版本: v3.0   日期: 2026-10-29
  对应固件: Eclipse/source/can_proto.h
--------------------------------------------------------------------------------
  本协议取代 CAN.txt / CANv2.txt 中"货架灯、钢网推动"等与本设备无关的部分。
  本设备只做两件事：把步进电机开到指定工位，然后执行固定舵机动作。
================================================================================


一、物理层与拓扑
--------------------------------------------------------------------------------
  * CAN 2.0B，扩展帧（29 位 ID），1 Mbps，标准 120Ω 终端，总线型拓扑。
  * 一台主控/网关带 3 台执行设备，节点地址 1 / 2 / 3（固件内 SLAVE_ADDR）。
  * 每台设备管理 100 个储位（以下简称"工位"），工位号 1~100（从 1 开始）。
  * 设备上电后自动自检 + 标定，不需要上位机触发。


二、CAN ID 规则
--------------------------------------------------------------------------------
  上位机 -> 设备：  0x10000000 | 节点号        节点号 = 0x001 ~ 0x3FF
                    节点号 = 0x000 表示广播（所有设备都收）
                    例：设备1 -> 0x10000001，广播 -> 0x10000000
  设备 -> 上位机：  0x00000100 | 节点号
                    例：设备1 -> 0x00000101，设备3 -> 0x00000103

  设备只处理"本机 ID"和"广播 ID"的帧，其它 ID 直接丢弃。
  设备不会主动发广播帧（避免 3 台同时应答撞帧）。


三、帧格式（分帧规则）
--------------------------------------------------------------------------------
  每条"消息"由 1~11 个 CAN 帧组成，每个 CAN 帧固定 8 字节结构：

      字节0  CMD   命令字
      字节1  SEQ   bit7 = MORE 标记：1 = 后面还有帧，0 = 本帧是最后一帧
                   bit6..0 = 消息序号 0~127，设备应答时原样回显该序号
      字节2  LEN   本条消息的数据总长度（不含这 3 字节头），0~63
      字节3..7     DATA，每帧最多 5 字节；最后一帧不足 5 字节时 DLC 相应减小

  规则：
  1) 同一条消息的所有帧，CMD / SEQ / LEN 三个头字节完全相同，只有 DATA 在往后接。
  2) 接收方按 LEN 收满即完整；收到 MORE=0 的帧立即处理。
  3) 同一时刻只重组 1 条消息。若收到的帧 CMD 或 SEQ 与正在重组的不一致，
     丢弃未完成的重组，从本帧重新开始（相当于丢帧保护）。
  4) 长消息示例（51 字节数据，11 帧）：
       帧1: 03 80 33 | 05 1E 03 0C 2D      (SEQ bit7=1，后面还有)
       帧2: 03 80 33 | 01 ...
       ...
       帧11:03 00 33 | xx                   (SEQ bit7=0，末帧)
  5) 单帧消息 DLC 建议 = 3 + 数据长度（不超过 8）。
  6) 不需要应用层 CRC，CAN 硬件自带 15 位 CRC；头字节重复出现本身也是一种自校验。


四、公共码表
--------------------------------------------------------------------------------
  [状态 STATE]  设备当前所处阶段，出现在 0x81/0x82/0x86 里
      0x00  IDLE        空闲
      0x01  SELFCHECK   自检中
      0x02  HOMING      回零中
      0x03  CALIB       标定（扫描凸点）中
      0x04  MOVING      步进运动中
      0x05  SERVO       舵机动作中
      0x06  FAULT       故障停机，等 0x05 清除

  [故障等级 LEVEL]
      0x01  警告：仅上报，任务继续
      0x02  错误：停止当前任务，设备可继续接单
      0x03  致命：急停 + 舵机释放扭力 + 步进失能，必须发 0x05 清除

  [故障码 CODE]（0x89 上报用）
      0x01  过流（总轨 > 2500 mA）            L3
      0x02  步进掉电 / 位置丢失                L3
      0x03  步进堵转                           L2
      0x04  回零超时 / 限位失效                L3
      0x05  舵机无应答                         L2
      0x06  上位机心跳丢失                     L3
      0x07  自检 / 标定失败（重试后仍失败）    L3
      0x08  皮带偏差超限（只报不补偿）         L1
      0x09  指令或参数非法                     L2
      0x0A  位置异常（超行程 / 未到位）        L2
      0x0B  驱动或电机过温                     L2

  [故障来源 SRC]
      0x01 步进   0x02 舵机   0x03 电源/电流
      0x04 通信   0x05 标尺/皮带   0x06 系统


五、命令总表
--------------------------------------------------------------------------------
  上位机 -> 设备                        设备 -> 上位机
  0x01  查询设备信息                    0x81  信息应答
  0x02  PING 心跳                       0x82  PING 应答
  0x03  工位任务（1~50 个，顺序任意）   0x83  收到确认（立即）
                                        0x84  总完成上报（任务结束时唯一一条）
  0x04  停止当前任务                    0x84  RESULT=0x05
  0x05  清除故障                        0x85  清除应答 + 0x88 自检事件
  0x06  查询状态                        0x86  状态应答
  0x07  重新标定凸点（换皮带后用）      0x87  标定进度/结果
  0x08  读取当前补偿量                  0x8A  补偿量上报
  0x09  去 0 点位（不重新回零）         0x8B  去 0 点位应答
  0x0F  调试信息（台架用）              0x8F  调试信息（每 2s 自动上报）
                                        ---- 以下为设备主动上报 ----
                                        0x88  自检 / 标定事件
                                        0x89  故障上报
                                        0x8A  补偿量（每次更新自动上报）
                                        0x8F  调试信息（固件开关 CAN_DEBUG_REPORT）

  注：任务执行过程中设备只发 2 条消息（0x83 收到、0x84 完成），不逐工位上报。


六、命令详细定义
================================================================================

*** 0x01 查询设备信息  ->  0x81 信息应答
--------------------------------------------------------------------------------
  下发:  CMD=0x01  LEN=0  （无数据）
  应答:  CMD=0x81  LEN=8
         [VER][FW_MAJOR][FW_MINOR][SLOT_TOTAL][STATE][FAULT][ADDR][CAP]
         VER        协议版本，固定 0x03
         FW_MAJOR/FW_MINOR  固件版本
         SLOT_TOTAL 工位总数，固定 100
         STATE      见状态码
         FAULT      当前故障码（0 = 无故障）
         ADDR       本机节点号 1~3
         CAP        能力位：bit0=舵机 bit1=脉冲补偿 bit2=支持重新标定 bit3=支持任务排队

  例:  [0x10000001] 01 05 00
       [0x00000101] 81 05 08 | 03 01 00 64 00 00 01 0F


*** 0x02 PING 心跳  ->  0x82 PING 应答
--------------------------------------------------------------------------------
  下发:  CMD=0x02  LEN=0
  应答:  CMD=0x82  LEN=2  [STATE][FAULT]

  规范：
   * 上位机每 500 ms 给每台设备发 1 次 PING（单播，不建议广播）。
   * 任何来自上位机的有效帧都会刷新设备的心跳计时器，PING 是最低要求。
   * 设备超过 3 s 未收到任何上位机帧 -> 上报 0x89 CODE=0x06 (L3) 并停机。
   * 设备不主动发心跳，只被动应答。

  例:  [0x10000002] 02 11 00
       [0x00000102] 82 11 02 | 00 00


*** 0x03 工位任务  ->  0x83 收到确认 + 0x84 总完成
--------------------------------------------------------------------------------
  下发:  CMD=0x03  LEN=N+1
         [N][S1][S2]...[SN]
         N   工位数 1~50
         Si  工位号 1~100，顺序任意，可重复

  收到后 100 ms 内必须应答 0x83（表示已收下、已排队）：
         [RESULT][N][QUEUE_IDX]
         RESULT    0x00 已接受   0x01 队列已满   0x02 参数非法
         N         本次接受的工位数
         QUEUE_IDX 本任务在队列中的位置，0 = 立即执行，1/2/3 = 前面还有几个任务

  任务结束时（成功或失败）只上报 1 条 0x84：
         [RESULT][DONE][SLOT]
         RESULT    0x00 全部完成
                   0x01 回零失败
                   0x02 运动超时 / 未到位
                   0x03 舵机动作失败
                   0x04 工位号非法
                   0x05 被 0x04 停止
                   0x06 故障中断（原因见同时发出的 0x89）
                   0x07 复位/掉电中断
                   0x08 工位都做完了，但自动回 0 位失败
         DONE      实际完成的工位数
         SLOT      出错或停止时所在的工位号；成功时为最后一个执行的工位号
        额外约定：任务做完后设备会**自动走回 0 点位**，回到 0 位之后才发 0x84；
        所以收到 0x84 时机器已经停在 0 位。回 0 失败时 RESULT=0x08。

  执行规则（设备内部）：
   * 设备会对 N 个工位重新排序：从当前实际位置出发，每次挑剩余工位中行程最短的，
     所以**不要依赖包内顺序**，也不要再替设备排序。
   * 每个工位：运动 -> 到位确认 -> 执行固定舵机动作 -> 下一个工位。
   * 任一步失败立即中断整个任务，回 0x84（带出错工位），不再动。
     同时队列里剩下的任务全部作废，每条回一个 0x84 [0x06 故障中断]，避免上位机干等。
   * 运行中收到新的 0x03：立即回 0x83（QUEUE_IDX=1/2/3），当前任务跑完后接着执行。
   * 队列最多缓存 3 个待执行任务，满了回 0x83 RESULT=0x01。

  例:  下发 5 个乱序工位 {30,3,12,45,1}，共 6 字节 -> 2 帧   （注意 LEN=06 而不是 08）
       [0x10000001] 03 80 06 | 05 1E 03 0C 2D
       [0x10000001] 03 00 06 | 01

  LEN 速查： N 个工位 -> LEN = N+1 -> 帧数 = ceil((N+1)/5)
         N=1~4  : LEN=02~05   1 帧
         N=5~9  : LEN=06~0A   2 帧
         N=10~14: LEN=0B~0F   3 帧
         N=50   : LEN=33      11 帧
       应答: [0x00000101] 83 00 03 | 00 05 00          (已收下，立即执行)
       完成: [0x00000101] 84 00 03 | 00 05 2D          (5 个全做完，最后到 45)
       失败: [0x00000101] 84 00 03 | 02 02 0C          (第 3 个工位 12 运动超时)


*** 0x04 停止当前任务  ->  0x84
--------------------------------------------------------------------------------
  下发:  CMD=0x04  LEN=0
  动作:  步进立即停止、舵机暂停并释放扭力、清空任务队列
  应答:  CMD=0x84  LEN=3  [0x05][DONE][当前工位]
         SEQ 回显：有任务在执行时回显"被终止任务"的 SEQ（上位机据此结束该任务）；
         空闲时回显 0x04 自己的 SEQ。


*** 0x05 清除故障  ->  0x85 应答 + 0x88 自检事件
--------------------------------------------------------------------------------
  下发:  CMD=0x05  LEN=0
  应答:  CMD=0x85  LEN=1  [RESULT]
         RESULT  0x00 已清除，开始重新使能 + 自检
                 0x01 清除失败（故障源仍在，例如过流仍在）
  之后：设备软件重新使能（本机无电源开关）：
        步进重新使能 -> 舵机恢复扭力 -> 回零 -> 读/校验补偿数据
        过程用 0x88 事件上报，结果用 0x88 RESULT=0/故障码

  说明：L3 故障清除前，设备不响应 0x03 任务（回 0x83 RESULT=0x02）。


*** 0x06 查询状态  ->  0x86
--------------------------------------------------------------------------------
  下发:  CMD=0x06  LEN=0
  应答:  CMD=0x86  LEN=8
         [STATE][FAULT][SLOT_TOTAL][CUR_SLOT][POS_H][POS_L][QUEUE][DONE]
         STATE       见状态码
         FAULT       当前故障码
         SLOT_TOTAL  100
         CUR_SLOT    当前/最后执行的工位号，0 = 无
         POS_H/POS_L  当前位置，单位 0.1 mm，16 位无符号（0~6553.5 mm）
         QUEUE       还有几个任务在排队
         DONE        当前任务已完成的工位数


*** 0x07 重新标定凸点（换皮带后使用）  ->  0x87
--------------------------------------------------------------------------------
  下发:  CMD=0x07  LEN=0
  动作:  清除当前补偿量 -> 回零 -> 全行程重新扫描记录凸点 -> 写 Flash 保存
  应答:  CMD=0x87  LEN=2  [STAGE][RESULT]
         STAGE  0x00 已接受，开始标定
                0x01 标定完成
                0x02 标定失败（RESULT = 原因，取故障码，如 0x07）
  完成后自动发 0x8A 补偿量（此时为新的、通常接近 0 的补偿值）。

  与开机自动标定的区别：开机只在"没有已存数据"时才标定；0x07 是无条件重新记录。


*** 0x08 读取补偿量  ->  0x8A
--------------------------------------------------------------------------------
  下发:  CMD=0x08  LEN=0
  应答:  CMD=0x8A（格式见下）


*** 0x09 去 0 点位  ->  0x8B
--------------------------------------------------------------------------------
  下发:  CMD=0x09  LEN=0
  动作:  步进直接走到坐标 0（回零后的原点），**不重新回零、不碰限位**，
         不去动舵机、不清补偿。
  应答:  CMD=0x8B  LEN=3  [RESULT][0][0]
         0x00 已接受，开始运动（立即回）
         0x01 已到达 0 点（到位后回）
         0x02 未到位/超时（同时发 0x89 CODE=0x0A L2）
         0x03 正在执行任务，拒绝（先发 0x04 停止或等任务结束）

  例:  [0x10000001] 09 00 00
       [0x00000101] 8B 00 03 | 00 00 00      已接受
       [0x00000101] 8B 00 03 | 01 00 00      已到 0 点

  说明：0x03 任务包执行结束后设备**自动**回 0 位，不需要再发这条指令；
        这条指令用于手动把机构挪回原点（例如上料前对齐）。


*** 0x88 自检 / 标定事件（设备主动上报）
--------------------------------------------------------------------------------
  CMD=0x88  LEN=3  [EVENT][RESULT][DETAIL]
      EVENT   0x01 自检开始
              0x02 自检完成
              0x03 标定开始
              0x04 标定完成
              0x05 自检中止（进入故障态）
              0x06 标定第 N 轮开始（RESULT=开始时凸点传感器电平，DETAIL=N）
              0x07 标定第 N 轮结束（RESULT=已确认点数，DETAIL=本轮检出凸点边沿数；
                   0xFF=本轮超时，0xFE=超程保护）
              0x08 回 0 位（RESULT：0=开始 1=位置到位 2=撞限位 3=超时失败
                    4=位置读不到，改用整行程+限位回零  5=位移异常，改用整行程回零）
      RESULT  0 = 成功；非 0 = 故障码（EVENT=0x02/0x04/0x05 时有效）
      DETAIL  EVENT=0x02 时：1=回零阶段 2=读取已存数据 3=标定阶段
              EVENT=0x04 时：本次确认的凸点数量
              EVENT=0x05 时：标定失败原因（3=超时 5=位置错误 6=回零失败 9=点数不足）
              其它：0

  开机流程（自动，不发预计耗时）：
     1) 0x88 [0x01][0][0]                 自检开始
     2) 回零（撞限位 -> 清堵转 -> 置 0 点）
     3) 读 Flash 里的凸点位置与补偿量
        有数据 -> 跳过标定，直接 0x8A 上传补偿量
        无数据 -> 0x88 [0x03][0][0] 标定开始 -> 全行程扫描记录凸点 -> 写 Flash
                -> 标定结束自动走回 0 点位
     4) 标定失败自动回 0 位后重试 1 次（重试前先重新回零），
        仍失败 -> 回 0 位 + 0x88 [0x05][0x07][3] + 0x89 CODE=0x07
     5) 0x88 [0x02][结果][阶段]            自检完成（此时机构已在 0 位）


*** 0x89 故障上报（设备主动上报）
--------------------------------------------------------------------------------
  CMD=0x89  LEN=5  [CODE][LEVEL][SRC][PARAM_H][PARAM_L]
      CODE/LEVEL/SRC  见公共码表
      PARAM           附加数据，无则 0：
                      CODE=0x01 过流    -> 实测电流 mA
                      CODE=0x07 自检失败 -> 失败时机构所在位置 mm（0=位置读取失败）
                      CODE=0x08 偏差    -> 斜率偏差 ppm
                      CODE=0x0A 位置    -> 目标脉冲低 16 位

  上报时机：故障发生时立即发 1 次；同一故障不重复刷屏（状态变化才再发）。
  L3 故障上报后设备已处于急停：舵机释放、步进失能，等 0x05 清除。


*** 0x8A 补偿量上报
--------------------------------------------------------------------------------
  CMD=0x8A  LEN=8
      [SEQ][DECISION][A_H][A_L][B_H][B_L][MAXR][VALID]
      SEQ       补偿更新序号，每次更新 +1（上电从 0 开始），上位机据此判断是否有新值
      DECISION  0x00 正常
                0x01 零点偏差，已补偿
                0x02 皮带轻微拉伸，已补偿
                0x03 零点异常，未补偿（超上限）
                0x04 皮带明显异常（松/跳齿），未补偿（超上限）
                0x05 有效点不足/测量异常，未补偿
      A         int16，整体偏移，单位 0.01 mm，负数用补码
      B         int16，斜率（皮带拉伸），单位 ppm（1 ppm = 0.0001%）
      MAXR      最大单点残差，单位 0.01 mm（0~255）
      VALID     有效凸点数 0~10

  发送时机：
   * 开机自检/标定完成后自动发 1 次（有更新就发）
   * 0x07 重新标定完成后自动发 1 次
   * 上位机发 0x08 时立即回 1 次
   * 任务运行中若判定补偿量发生变化，自动发 1 次
  DECISION=0x03/0x04（超上限）时设备**只上报不补偿**，并同时发 0x89 CODE=0x08(L1)；
  DECISION=0x05（有效点不足/首次尚无参考位）只报补偿量，不算故障。


*** 0x0F 调试信息（台架用，出厂关闭）  ->  0x8F
--------------------------------------------------------------------------------
  CMD=0x8F  LEN=20
  [isr][rxf][acc][dis][RTIE][RTIF][RCTRL][ACFEN][CFGSTAT][TECNT][RECNT][ID(4B)][dlc]
  [servo_reply][servo_pos(2B)][servo_ok_cnt]
  isr      CAN 中断进入次数（累加，会回绕）
  rxf      从控制器读出并存入队列的帧数
  acc      通过 ID 过滤（本机/广播）的帧数
  dis      派发成命令消息条数
  RTIE/RTIF/RCTRL/ACFEN/CFGSTAT/TECNT/RECNT   CAN 寄存器快照
  ID       最近一次收到的原始 29 位 ID，dlc 为其长度
  servo_reply  0=没应答 1=收到 #OK! 2=收到位置回读
  servo_pos    最近一次回读的舵机位置（PWM 值）
  servo_ok_cnt 累计收到的 #OK! 次数（低 8 位）
  判读：isr 不动 -> 中断没进来；rxf=0 -> 滤波器没收；acc=0 -> ID 不匹配；
        acc>0 但无应答 -> 命令解析问题。
        servo_ok_cnt 不涨 -> 舵机根本没应答（查 USART3/ID/波特率）。


七、时序汇总
--------------------------------------------------------------------------------
  项目                     要求
  ------------------------------------------------------------------------------
  PING 周期                上位机每 500 ms 发 1 次
  心跳超时                 3 s 内没收到任何上位机帧 -> 0x89 0x06(L3) + 停机
  0x03 收到确认            收到后 100 ms 内回 0x83
  0x84 完成上报            任务结束立即发，整个任务只发 1 条
  单工位节拍               运动（≤3 s）+ 到位确认 + 舵机动作（固定，约 0.6 s）
  标定重试                 失败自动重试 1 次
  队列深度                 3 个待执行任务 + 1 个执行中
  上电到自检开始           上电后立即（无固定延时）


八、舵机动作（固定，协议内不参数化）
--------------------------------------------------------------------------------
  每个工位"确认到位 + 稳定 150ms"后自动执行，动作写死在固件（can_servo_cycle）：
      推到 2200 us（500 ms 行程）-> 再等 150 ms -> 保持 500 ms
      -> 回 1500 us 中位（500 ms 行程）-> 再等 150 ms -> 稳定 300 ms
  单工位节拍 = 运动时间 + 到位确认 + 稳定 150 ms + 舵机动作约 2.1 s
  如需改动作幅度/时间，改 can.h 里的 CAN_SERVO_* 宏，协议不变。

  步进到位判定：按行程算理论最短时间(最高速 480 mm/s，乘 1.4 余量 + 250 ms 启动)，
  时间到后再用 0x32 实际脉冲位置确认（容差 3 mm），不再单独依赖 PRF 到位标志。


九、典型会话
--------------------------------------------------------------------------------
  1) 上电
     [0x00000101] 88 00 03 | 01 00 00                自检开始
     [0x00000101] 88 01 03 | 02 00 01                自检完成，回零阶段 OK
     [0x00000101] 8A 02 08 | 00 01 00 08 00 00 03 08 补偿量更新（a=+8 <-0.08mm>，b=0，8 点）

  2) 下发任务 {12, 5, 40}
     [0x10000001] 03 04 04 | 03 0C 05 28
     [0x00000101] 83 04 03 | 00 03 00                已收下，立即执行
     （设备内部按就近排序，比如 5 -> 12 -> 40）
     [0x00000101] 84 04 03 | 00 03 28                全部完成

  3) 运行中又下发一个任务
     [0x10000001] 03 05 03 | 02 07 09
     [0x00000101] 83 05 03 | 00 03 01                已排队，前面还有 1 个任务

  4) 故障
     [0x00000101] 89 06 05 | 01 03 03 09 84          过流 2500mA，L3，电源
     （设备已急停：舵机释放、步进失能）
     [0x10000001] 05 07 00
     [0x00000101] 85 07 01 | 00                      已清除，开始自检
     [0x00000101] 88 08 03 | 01 00 00
     [0x00000101] 88 09 03 | 02 00 01
